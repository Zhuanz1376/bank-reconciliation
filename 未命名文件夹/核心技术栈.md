## 五、会计业务知识（★ 老师一定会追问，必须说准）

| 知识点 | 要点 | 一句话讲法 |
|---|---|---|
| 未达账项 | 一方已记账、另一方未记账 | "企业记了银行没记，或银行记了企业没记，共四种" |
| 未达账四大类 | 银已收企未收 / 银已付企未付 / 企已收银未收 / 企已付银未付 | "前两类调企业账面，后两类调银行对账单" |
| 余额调节表公式 | 企业账面 + 银收 − 银付 = 银行对账单 + 企收 − 企付 | "两边各自加减自己的未达账，调整后相等就说明账实相符" |
| 对账口径（3.5.5） | 结算方式+票号+借方金额+贷方金额 四字段全等 | "我的第一轮严格匹配和学习通 3.5.5 的判定完全一致" |
| 期初未达账结转 | 上月未达账本月仍在，要并入本月对账 | "期初企业方未达账会出现在本月银行对账单里，自动配对核销，这就是结转" |
| 借贷方向 | 企业：借=收入 贷=支出；银行对账单：借=企业存款增加 贷=减少 | "教材数据里两边借贷位置相同，所以四字段可以直接比，不用反向转换" |

## 八、演讲 Q&A 预案（老师最可能问的 6 个问题）

1. **Q：为什么要分两个文件？一个文件不行吗？**
   A：分层后算法能脱离界面做单元测试，以后换 Web 界面算法一行不改；这也是软件工程里的单一职责原则。

2. **Q：容错匹配会不会把不相干的流水错配？**
   A：有可能（同名票号同金额），所以我做了三件事：只做兜底、界面 ？标记淡黄底提示人工复核、README 的"已知不足"里写明改进方向——对账结果最终由会计确认，程序只辅助。

3. **Q：为什么金额比较不用 ==？**
   A：二进制浮点无法精确表示 0.1 这类小数，3624.78 存进去可能是 3624.7800000001，我用了 ±0.005 元容差和 round(…,2)。

4. **Q：期初未达账为什么要结转？**
   A：上月的银行已收企业未收，这个月企业账上总会记到，结转进来才能和本月对账单配对核销，否则会重复挂账。

5. **Q：exe 多大？为什么这么大？**
   A：47MB 左右，因为打包了完整的 Python 解释器和依赖库，换来的是客户零安装。

6. **Q：怎么证明你的对账结果是对的？**
   A：18 个单元测试，用教材标准答案当断言——22 对已达、4+4 未达、两端调整后 448,067.78 平衡；另外调节表本身就是业务上的自校验，两端不等会红色报警。
