# 出纳管理之银行对账系统 v2

> 一个用 Python + Tkinter 开发的桌面小工具：把**单位银行存款日记账**与**银行对账单**自动逐笔核对，区分已达 / 未达账项，自动生成《银行存款余额调节表》，并可一键打包成 exe 交付使用。
>
> 核心对账口径在标准的"四字段全等严格匹配"基础上，增加了两轮容错匹配、余额自动滚动、项目持久化三项能力，以适配真实录入场景中的日期 / 票号写法差异。

## 四、对账算法详解

### 4.1 数据口径

- **企业方待对账** = 期初企业方未达账（自动结转） + 本期单位银行存款日记账
- **银行方待对账** = 期初银行方未达账（自动结转） + 本期银行对账单
- 每条流水五要素：`日期、结算方式、票号、借方金额、贷方金额`（借贷只填一侧）

### 4.2 三轮自动匹配

| 轮次 | 等级 | 匹配条件 | 界面标记 | 解决的问题 |
|---|---|---|---|---|
| 第 1 轮 | 严格 | **结算方式 + 票号 + 借方金额 + 贷方金额** 四字段全等 | √ | 四字段全等判定，结果可信 |
| 第 2 轮 | 容错 | 票号 + 金额 + 同方向 | ？ | 两边日期写法不一致（12.1 / 2025-12-01）导致的漏配 |
| 第 3 轮 | 容错 | 日期 + 金额 + 同方向 | ？ | 无票号、或票号写法不同的流水兜底 |

- 金额比较使用 **±0.005 元容差**，规避二进制浮点误差（`3624.78` 这类小数）；
- 严格匹配用**字典索引**实现，复杂度 O(n)，几千笔流水秒级完成；
- 容错匹配的配对**建议人工复核**，界面用淡黄底色 + ？标记区分——宁可多提醒，不替会计做决定。

### 4.3 未达账项四分类

未匹配的流水按记账方向自动归类：

| 类别 | 判定 |
|---|---|
| 企业已收，银行未收 | 企业方剩余，借方 > 0 |
| 企业已付，银行未付 | 企业方剩余，贷方 > 0 |
| 银行已收，企业未收 | 银行方剩余，借方 > 0（银行对账单借方 = 企业账户存款增加） |
| 银行已付，企业未付 | 银行方剩余，贷方 > 0 |

### 4.4 余额自动滚动

不再手工填期末余额。从期初开始逐笔滚动（双方同公式）：

```
本笔滚动余额 = 上一笔余额 + 借方金额 − 贷方金额
企业期末账面余额 = 企业期初 + 本期借方合计 − 本期贷方合计
银行期末对账单余额 = 银行期初 + 本期借方合计 − 本期贷方合计
```

期初结转记录（is_opening=True）不参与滚动，余额置 0。

### 4.5 期末余额调节表（交叉调节口径）

```
企业侧调整后 = 企业期末账面   + (银行已收企业未收) − (银行已付企业未付)
银行侧调整后 = 银行期末对账单 + (企业已收银行未收) − (企业已付银行未付)
两端调整后余额相等  ⇔  对账平衡
```

> 平衡恒等式成立的前提是**期初调节表平衡**（期初两端调整后相等），因此程序在期初页就实时校验平衡。

## 五、界面功能与数据格式

### 5.1 界面分区

1. **① 余额调节起点**：期初余额录入，可从模板 Excel / CSV 载入；【保存项目】【打开项目】；
2. **② 本期流水录入 / 导入**：手工逐笔（借贷只填一侧）、导入 Excel（模板 Sheet1/2/3）、导入 CSV/TXT、删除选中行；
3. **③ 全部流水清单**：含期初结转与本期录入，显示滚动余额与对账标记，**双击任意行可修改 / 删除**；
4. **④ 未达账项明细**：四大类自动归类，标注期间（期初 / 本期）；
5. **⑤ 银行存款余额调节表**：等宽文本实时渲染，平衡 / 不平衡红绿提示；导出 Excel（6 个 Sheet）与 CSV。

### 5.2 支持的数据格式

| 格式 | 说明 |
|---|---|
| 流水 CSV | 列：`日期,结算方式,票号,借方金额,贷方金额[,期末余额]`，支持 UTF-8 / 带 BOM；`合计`行自动剔除 |
| 期初 CSV | `[节名]` 分节：企业日记账期初余额 / 银行对账单期初余额 / 期初企业方未达账 / 期初银行方未达账，`#` 开头为注释 |
| 模板 Excel | Sheet1=期初调节表（含未达账明细）、Sheet2=日记账、Sheet3=对账单、Sheet4=期末（导出用） |
| 项目 JSON | 全部数据 + 期初状态 + 对账统计，**关掉软件不丢账**，exe 客户可断点续作 |

日期兼容 `2025-12-08 / 2025.12.8 / 2025/12/8`；金额兼容千分位与 `￥` 前缀。

## 六、pyinstaller 打包交付（产出④）

### Windows（交付客户，双击 `打包exe.bat`）

```bat
python -m pip install -r requirements.txt pyinstaller
python -m PyInstaller -F -w -n BankRecon ^
  --add-data "示例数据_单位银行存款日记账.csv;." ^
  --add-data "示例数据_银行对账单.csv;." ^
  --add-data "示例数据_期初余额调节表.csv;." ^
  银行对账系统.py
```

产物 `dist\BankRecon.exe`：**单文件、无黑窗口（-w）**，复制给客户后可改名"银行对账系统.exe"，双击即用，无需安装 Python。

### macOS / Linux（验证用）

```bash
python3 -m PyInstaller -F -w -n BankRecon \
  --add-data "示例数据_单位银行存款日记账.csv:." \
  --add-data "示例数据_银行对账单.csv:." \
  --add-data "示例数据_期初余额调节表.csv:." \
  银行对账系统.py
```

> 注意：Windows 下 `--add-data` 分隔符是 `;`，mac/linux 是 `:`。
> 本仓库已在 mac 上完成打包验证（主程序、核心模块、3 个 CSV 均在单文件包内）。

### 打包关键参数速记

| 参数 | 作用 |
|---|---|
| `-F` | 打成**一个** exe 文件，方便分发 |
| `-w` | 不弹黑色控制台窗口（GUI 程序必备） |
| `-n BankRecon` | 产物文件名 |
| `--add-data` | 把 CSV 示例数据打进包里 |
| `sys._MEIPASS` | 程序里兼容单文件模式的临时解压目录，`resource_path()` 统一处理 |

### 只有 macOS 怎么拿到 Windows exe？（三选一）

> pyinstaller 不支持交叉打包：Mac 上只能打 mac 程序，exe 必须在 Windows 环境里打。三条路按推荐顺序：

| 方案 | 做法 | 成本 |
|---|---|---|
| **① GitHub Actions 云端打包（推荐）** | 仓库里已配好 `.github/workflows/build-exe.yml`：把代码 push 到 GitHub，Actions 会自动在 GitHub 的 Windows 虚拟机里执行与 bat 相同的打包命令，跑完在 **Actions → 本次运行 → Artifacts** 下载 `BankRecon.exe` | 免费，约 3 分钟 |
| ② 虚拟机装 Windows | 用 UTM（免费）或 VMware Fusion（个人免费）/ Parallels（试用）装 Windows，虚拟机里装 Python 后双击 `打包exe.bat` | 首次装系统 1–2 小时 |
| ③ 借一台 Windows 电脑 | 整个 `银行对账系统/` 文件夹拷 U 盘，装好 Python 后双击 `打包exe.bat`，完事拷回 `dist\BankRecon.exe` | 几分钟 |

> 本机是 Mac，Windows exe 由 GitHub Actions 的云端 Windows 环境自动打包——push 代码即出 exe，这也是开源项目标准的 CI/CD 做法。（本机 `dist/BankRecon` 是 mac 版打包产物，用于本机验证。）

## 八、v1 → v2 演进与已知不足

### v2 相对 v1（单文件版）的完善

| # | 完善点 | 价值 |
|---|---|---|
| 1 | 核心逻辑抽到 `bank_core.py`，界面只做展示 | 算法可单测、可复用（换 Web 界面不用改算法） |
| 2 | 严格匹配采用**四字段全等**口径，再加两轮容错 | 既覆盖标准四字段全等口径，又解决实际录入差异 |
| 3 | 期末余额**自动滚动**计算 | 少填一列，杜绝手填错误 |
| 4 | **项目保存 / 打开**（JSON） | 关软件不丢账，exe 客户可续作 |
| 5 | 双击流水行弹窗修改、菜单栏、导出含匹配等级 | 操作效率与可追溯性 |
| 6 | 18 项单元测试 + 打包验证 | 改动有护栏，交付有底气 |

### 已知不足（后续改进方向）

1. **容错匹配仍可能误配**：同名票号 + 同金额的两笔无关流水会被第 2 轮配对。改进方向：加入日期接近度校验，或提供"人工勾对"界面把 ？改判为未达；
2. **多借多贷拆分业务**：一笔业务拆成多笔入账时无法自动匹配。改进方向：支持"一对多"合并匹配或金额分摊；
3. **无银行流水标准格式接入**：目前只支持 CSV/Excel 模板。改进方向：接入银行网导出的标准对账单格式；
4. **界面为单机版**：无多人协作、无数据库。改进方向：SQLite 存储多人账套。
